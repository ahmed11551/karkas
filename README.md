# Каркасник — дачные каркасные дома в Москве и МО

Премиальный лендинг и интерактивный сервис для продажи каркасных дачных домов «под ключ»:
каталог проектов, живой калькулятор стоимости, квиз, сборка сметы, заявки, CRM для менеджеров
с обновлениями в реальном времени.

> **Что умеет система:** каталог → расчёт → квиз → лид → CRM в realtime

> Локальный запуск: `http://localhost:3000` · CRM: `http://localhost:3000/login`  
> Публичный URL: поднимите временный туннель (`npx localtunnel --port 3000`) или задеплойте на Railway/VPS — см. раздел «Деплой».  
> Живой сайт: https://karkasnik57.ru

## Демо для комиссии

| Что | Как |
| --- | --- |
| Сайт | `npm run dev` → http://localhost:3000 |
| CRM | http://localhost:3000/login |
| Логин / пароль | только в локальном `.env` (см. [`DEFENSE.md`](./DEFENSE.md), файл `.env` в git не попадает) |
| Сценарий | главная → каталог → калькулятор/квиз → заявка → CRM видит лид в realtime |

Перед защитой: `cp .env.example .env` и задайте `ADMIN_LOGIN` / `ADMIN_PASSWORD` (пароль ≥ 12 символов).

Краткая структура доклада — в [`DEFENSE.md`](./DEFENSE.md).

## Возможности

- **Каталог** 15 типовых проектов (от 16 до 110 м²) с фильтрами по бюджету и стилю.
- **Калькулятор** стоимости: площадь, утепление, фундамент, веранда, удалённость от МКАД.
- **Квиз** с подбором комплектации и отправкой заявки.
- **Смета**: просмотр, печать или сохранение в PDF через системное окно печати, копирование ссылки на расчёт.
- **Заявки** сохраняются на сервере и доступны в CRM (`/login`).
- **CRM**: список лидов, карточка лида, заметки менеджера, статусы, экспорт в CSV.
- **Realtime**: новые заявки приходят администратору через Server-Sent Events без перезагрузки.
- **Заявки**: источник, путь страницы и UTM сохраняются. Повтор с тем же телефоном в течение 3 минут не создаёт вторую заявку.
- **События**: `view_project`, `calc_start`, `calc_complete`, `quiz_start`, `quiz_complete`, `lead_submit`, `crm_status_change` уходят в `dataLayer` и в Метрику, если задан `VITE_YANDEX_METRIKA_ID`.
- **Двуязычный интерфейс** (русский / английский), светлая и тёмная темы, звуковые эффекты (по желанию).
- **Безопасность**: HttpOnly-сессия администратора, rate limit, CSP, защита от CSV-инъекций, валидация на сервере.

## Переменные окружения

Все настройки берутся из `.env` (шаблон — `.env.example`). Файл `.env` не попадает в git.

| Переменная | Обязательна | Описание |
| --- | --- | --- |
| `ADMIN_LOGIN` | да (для входа в CRM) | Логин администратора, не короче 3 символов |
| `ADMIN_PASSWORD` | да (для входа в CRM) | Пароль администратора, не короче 12 символов. Встроенного пароля нет |
| `HOST` | нет | Адрес, на котором слушает сервер. По умолчанию `0.0.0.0`. Для локальной работы — `127.0.0.1` |
| `PORT` | нет | Порт сервера. По умолчанию `3000` |
| `NODE_ENV` | нет | `development` или `production` |
| `TRUST_PROXY` | нет | `1`, только если сервер стоит за доверенным reverse proxy (Nginx, Railway, Render и т.п.). Без него лимиты запросов видят IP прокси |
| `ALLOWED_ORIGINS` | нет | Список источников через запятую, которым разрешён API с cookies. Пусто — только same-origin |
| `DATA_DIR` | нет | Папка для `leads.json`. Пусто — `./data` в проекте. На хостинге укажите путь постоянного диска (volume). Перед переносом скопируйте этот файл: это единственная копия заявок |
| `FRAME_ANCESTORS` | нет | Кто может встраивать сайт в `iframe`. Пусто — только `'self'` |
| `TELEGRAM_BOT_TOKEN` | нет | Токен бота от @BotFather. Вместе с `TELEGRAM_CHAT_ID` включает уведомления о новых заявках |
| `TELEGRAM_CHAT_ID` | нет | ID чата или канала (для групп — отрицательное число). Без обоих значений уведомления выключены |
| `VITE_YANDEX_METRIKA_ID` | нет | Числовой ID счётчика Яндекс.Метрики (4–12 цифр). Пусто — метрика отключена |

### Поведение без `.env`

- **Режим разработки** (`NODE_ENV` не `production`): сервер запускается, но вход администратора
  отключён. В консоли появляется предупреждение `[auth] ADMIN_LOGIN / ADMIN_PASSWORD are not set`,
  а `POST /api/auth/login` возвращает `503 AUTH_DISABLED`. Публичный сайт при этом работает полностью.
- **Production** (`NODE_ENV=production`): сервер **не стартует**, пока не заданы корректные
  `ADMIN_LOGIN` и `ADMIN_PASSWORD`. Это защищает от развёртывания с известным или пустым паролем.

## Деплой

Проект состоит из фронтенда (`dist/`) и Node-сервера `server.ts`. Сервер отдаёт API, CRM, SSE-поток
`/api/leads/stream` и хранит заявки в файле `leads.json`. Поэтому хостинг должен запускать долгоживущий
Node-процесс и давать постоянный диск. **Vercel и Netlify для этого проекта не подходят**: их serverless-модель
не держит SSE-поток и не сохраняет файл между запусками.

Подходят: **Railway**, **Render** (диски на платном плане) и **VPS** с Node.js и Nginx.

### Перед деплоем

- **Node.js** `^20.19.0 || >=22.12.0` (задано в `engines`, это требование Vite 8).
- **Lockfile.** Проект работает на npm: `package-lock.json` должен лежать в репозитории рядом с `package.json`.
  `bun.lock` не синхронизирован с `package.json` и для деплоя не используется. Без lockfile `npm install`
  берёт самые свежие версии в пределах диапазонов из `package.json`.
- **Один экземпляр.** Заявки хранятся в файле, поэтому запускайте одну копию сервера. Несколько реплик
  будут писать в разные файлы, а SSE-уведомления придут только одной из них.
- **Не используйте `npm install --omit=dev`.** Сборка и `npm run lint` используют devDependencies.
- **Персональные данные и 152-ФЗ.** Заявки содержат ФИО и телефон граждан РФ. По ч. 5 ст. 18 152-ФЗ их нужно
  хранить на серверах в РФ. Railway и Render работают в зарубежных регионах, поэтому для продакшена
  выбирайте хостинг в РФ или подтвердите вопрос с юристом (см. пункт в разделе «Юридические документы»).

### Команды сборки и запуска

```bash
npm install                    # все зависимости, включая devDependencies
npm run build                  # фронтенд в dist/
NODE_ENV=production npm start  # сервер: отдаёт dist/ и API
```

`npm start` запускает `tsx server.ts`. Поэтому `tsx` стоит в `dependencies`, а не в `devDependencies`.

### Переменные окружения на хостинге

Задайте их в панели платформы. Файл `.env` в git не попадает и на сервер не переносится.

| Переменная | Значение на хостинге |
| --- | --- |
| `NODE_ENV` | `production` (без этого сервер не включит production-режим) |

| `TRUST_PROXY` | `1` (Railway, Render и Nginx стоят перед приложением) |

| `ALLOWED_ORIGINS` | Пусто, если сайт и API на одном домене |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | По желанию. Уведомления о заявках |
| `VITE_YANDEX_METRIKA_ID` | По желанию. Значение нужно **на этапе сборки**: Vite вшивает его в бандл. Задайте его до `npm run build` и пересоберите после изменения |

`HOST` обычно не задают: по умолчанию `0.0.0.0`. `PORT` платформа передаёт сама.

### Railway

1. **New Project → Deploy from GitHub repo** и выберите репозиторий.
2. **Settings → Build Command:** `npm install && npm run build`. **Start Command:** `npm start`.
3. **Variables:** добавьте переменные из таблицы выше.
4. **Settings → Volumes → Add Volume.** Mount path: `/app/data`. Затем задайте `DATA_DIR=/app/data`.
   Путь контейнера зависит от образа. Если Railway показывает другой путь, используйте его.
5. **Settings → Healthcheck Path:** `/api/health`.
6. **Settings → Networking → Generate Domain.**

### Render

1. **New → Web Service** и подключите репозиторий. Runtime: **Node**.
2. **Build Command:** `npm install && npm run build`. **Start Command:** `npm start`.
   Версия Node берётся из `engines`. При необходимости задайте `NODE_VERSION`.
3. **Environment:** добавьте переменные из таблицы выше.
4. **Health Check Path:** `/api/health`.
5. **Disks → Add Disk.** Mount path: `/var/data`. Затем задайте `DATA_DIR=/var/data`.
   Диски доступны только на платных планах. Сервис с диском нельзя масштабировать на несколько экземпляров.

### VPS (Node + Nginx)

Запустите сервер через systemd или pm2 с `HOST=127.0.0.1` и `TRUST_PROXY=1`. Nginx проксирует запросы,
а SSE-поток нужно отдавать без буферизации, иначе уведомления CRM будут приходить с задержкой:

```nginx
location /api/leads/stream {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_cache off;
    proxy_read_timeout 1h;
}

location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

### Резервные копии

Заявки хранятся в одном файле `DATA_DIR/leads.json`. Настройте регулярную копию этого файла: снимки диска
у провайдера или `cron` с копированием на другой сервер.

## Вход администратора (CRM)

1. Откройте `/login` или нажмите `Alt + L` на любой странице.
2. Введите значения `ADMIN_LOGIN` и `ADMIN_PASSWORD` из вашего `.env`.
3. После входа появится кнопка CRM в шапке сайта.

Учётных данных по умолчанию в проекте нет: логин и пароль задаются только в `.env`
и никогда не записываются в код или README. Сессия:

- сервер выдаёт cookie `karkas_admin` с флагами `HttpOnly` и `SameSite=Strict`;
- обычная сессия живёт **12 часов**, при «запомнить меня» — **7 дней**;
- попытки входа ограничены: **8 запросов за 15 минут** с одного IP.

## CRM и обновления в реальном времени (SSE)

**Фильтры CRM.** Поиск по имени, телефону, проекту, заметкам и ID. Фильтры по статусу, источнику
(квиз, калькулятор, каталог, быстрая заявка) и периоду дат. Кнопка «Сбросить» очищает все фильтры.
«Экспорт CSV» выгружает заявки, которые видны с текущими фильтрами.

**Telegram.** Если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`, сервер отправляет в чат
сообщение о каждой новой заявке (имя, телефон, проект, сумма, источник). Отправка не задерживает
ответ клиенту. Ошибки Telegram пишутся в лог без токена. Сообщение содержит персональные данные,
поэтому используйте приватный чат. Проверить подключение можно, отправив тестовую заявку через сайт.

**Заявки.** Публичная форма отправляет `POST /api/leads`. Сервер проверяет данные
(`parsePublicLead`), присваивает идентификатор вида `LD-XXXXXXXX` и статус `new`, и сохраняет
лид в `data/leads.json`. Лимит: **12 заявок за 10 минут** с одного IP.

**CRM** (`AdminLeadsDrawer`) работает через защищённые маршруты:

| Маршрут | Назначение |
| --- | --- |
| `GET /api/auth/verify` | Проверка сессии администратора |
| `GET /api/leads` | Список лидов (только для администратора) |
| `GET /api/leads/stream` | Поток SSE с новыми заявками (только для администратора) |

**SSE.** После входа браузер открывает `EventSource('/api/leads/stream')`. Сервер:

1. отправляет событие `connected` с `{ "status": "ok" }`;
2. при каждой новой заявке рассылает событие `new_lead` всем подключённым администраторам.

Клиент получает `new_lead`, обновляет счётчик новых заявок, показывает всплывающее
уведомление и генерирует событие `leads_updated` для перерисовки списка. Соединение
закрывается при выходе или закрытии вкладки.

## Мобильная версия, PWA, аналитика и смета

- **Мобильная панель** (`StickyMobileBar`): звонок, WhatsApp и кнопка калькулятора внизу экрана.
  Учитывает safe-area на iPhone.
- **Мессенджеры** (`MessengerFloating`): кнопка открывает панель с Telegram и WhatsApp.
  Закрывается по `Esc`, имеет `aria-expanded` / `aria-controls`, тексты берутся из `translations.ts`.
- **Смета в PDF**: кнопка «Печать / PDF» вызывает системное окно печати. Для печати показывается
  только лист сметы (`@media print` в `src/index.css`, атрибуты `data-print-area`).
  Сторонние библиотеки для PDF не используются.
- **Яндекс.Метрика**: включается, только если в `.env` задан `VITE_YANDEX_METRIKA_ID`
  (числовой ID счётчика). Без ID скрипт не загружается, а CSP не разрешает `mc.yandex.ru`.
  Счётчик грузится только в production-сборке. Цель `lead_sent` срабатывает после успешной отправки заявки.
  Перед включением добавьте в политику конфиденциальности раздел о cookies и аналитике
  и предусмотрите согласие пользователя.
- **PWA**: `public/manifest.webmanifest`, service worker `public/sw.js` и иконки в `public/icons/`.
  Service worker регистрируется только в production (`src/utils/pwa.ts`). Кэшируются статика
  (`/assets/`, `/images/`, `/icons/`) и оболочка приложения. Запросы `/api/*` и сторонние домены
  service worker не перехватывает.
- **Обработка ошибок**: `ErrorBoundary` показывает понятный экран вместо белого экрана при сбое рендера.

## Юридические документы

Тексты политики обработки персональных данных и пользовательского соглашения лежат в
`src/data/legal.ts` (RU и EN). Они открываются из футера и по адресам `/privacy` и `/terms`.
Чекбокс согласия в формах ссылается на политику.

**Тексты не являются юридической консультацией.** Перед запуском их должен проверить юрист. Пункты,
которые зависят от бизнеса, помечены комментарием `REVIEW` в `src/data/legal.ts`:

- срок хранения заявок (сейчас «до 3 лет после последнего обращения»);
- условия фиксации цены и подарков (сейчас 14 дней);
- порядок оплаты (сейчас без предоплаты, расчёт после монтажа) и гарантия из `COMPANY_CONFIG.warrantyMonths`;
- утверждение «персональные данные граждан РФ хранятся на серверах в РФ». Это правда только если сайт и база
  заявок размещены в России. Учитывайте это при выборе хостинга.
- реквизиты ООО в `src/config/company.ts` (ИНН, ОГРН, адреса) нужно сверить с учредительными документами.

В смете (PDF) есть утверждения «включая НДС» и «смета заверена главным инженером». Их тоже нужно подтвердить.

Яндекс.Метрика и Telegram-уведомления упомянуты в политике как поставщики. Если вы их отключаете,
обновите раздел 6 в `src/data/legal.ts`.
